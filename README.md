# Сайт для продажи ключей VPN

Сайт в стиле Apple: главная страница с тарифами, регистрация по почте и паролю, личный кабинет. После оплаты подписки человек сам создаёт ключи (до `MAX_KEYS` штук, по одному на устройство) и получает ссылку `vless://` и QR-код. Когда подписка заканчивается, его ключи удаляются с сервера автоматически (проверка раз в 5 минут).

Сайт работает на том же сервере, что и VPN (`install-vpn.sh`), и правит тот же конфиг Xray, что и Telegram-бот. Ключи с сайта подписаны в Xray как `w<номер пользователя>_<имя>`, поэтому не путаются с ключами бота. Бот можно оставить: в его `/keys` ключи сайта видны как ключи админа.

Что внутри: Python (Flask), база SQLite в `/var/lib/vpn-site/site.db`, Caddy для HTTPS.

| Страница | Что там |
|---|---|
| `/` | главная: возможности, тарифы, как подключиться |
| `/register`, `/login` | регистрация и вход |
| `/account` | статус подписки, оплата, ключи с QR-кодами |
| `/admin` | для почт из `ADMIN_EMAILS`: все пользователи, «+30 дней», «Снять подписку», «Заблокировать» |

## Быстрая установка одной командой

На чистом сервере Ubuntu или Debian от root:
```
bash <(curl -fsSL https://raw.githubusercontent.com/dsdsnfdjndfjhbhgfd-ops/vpn-site/main/install.sh) ВАША@ПОЧТА
```
Скрипт `install.sh` ставит Xray (VLESS Reality на порту 443), включает BBR, ставит сайт и Caddy с HTTPS на порту 8443 и в конце печатает адрес сайта и проверочный ключ. Без домена сайт получает бесплатный адрес вида `1-2-3-4.sslip.io`. Свой домен можно передать вторым словом: `... install.sh ВАША@ПОЧТА vpn.example.com`.

Оплата после установки выключена (`PAYMENTS_ENABLED=0`): подписку выдаёт админ в `/admin` кнопкой «+30 дней». Повторный запуск скрипта обновляет сайт и не трогает ключи.

Ниже то же самое по шагам, вручную.

## Что понадобится

1. Сервер с уже установленным VPN (`bash install-vpn.sh`).
2. Домен (например, `vpn.example.com`), у которого A-запись указывает на IP сервера. Без домена не будет HTTPS, а ЮKassa работает только с HTTPS.

Порт 443 занят VPN, поэтому сайт открывается на порту **8443**: `https://vpn.example.com:8443`. Порт 80 нужен Caddy, чтобы получить сертификат.

## 1. Скопируйте файлы на сервер

С компьютера, из папки `site`:
```
ssh root@IP_СЕРВЕРА mkdir -p /opt/vpn-site
scp -r app.py requirements.txt static templates vpn-site.service Caddyfile root@IP_СЕРВЕРА:/opt/vpn-site/
```

## 2. Установите сайт

На сервере:
```
apt-get install -y python3-venv
cd /opt/vpn-site
python3 -m venv venv
venv/bin/pip install -r requirements.txt

cat > /etc/vpn-site.env <<E
SECRET_KEY=$(python3 -c "import secrets; print(secrets.token_hex(32))")
BASE_URL=https://vpn.example.com:8443
SITE_NAME=Tunnel
ADMIN_EMAILS=ваша@почта.ru
MAX_KEYS=1
PLANS=1m:30:199:1 месяц,3m:90:499:3 месяца,12m:365:1690:12 месяцев
PAYMENT_PROVIDER=test
E
chmod 600 /etc/vpn-site.env

cp vpn-site.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now vpn-site
systemctl status vpn-site
```
Замените `vpn.example.com` на свой домен. Все настройки с пояснениями есть в `vpn-site.env.example`.

## 3. Включите HTTPS (Caddy)

```
apt-get install -y caddy
sed -i 's/vpn.example.com/ВАШ_ДОМЕН/' /opt/vpn-site/Caddyfile
cp /opt/vpn-site/Caddyfile /etc/caddy/Caddyfile
systemctl restart caddy
ufw allow 80/tcp; ufw allow 8443/tcp   # если включён ufw
```
Если `apt-get install caddy` не находит пакет, поставьте его по инструкции с caddyserver.com/docs/install (раздел Debian, Ubuntu).

Откройте `https://ВАШ_ДОМЕН:8443`, зарегистрируйтесь с почтой из `ADMIN_EMAILS` и проверьте всё в тестовом режиме: кнопка «Оплатить (тест)» сразу продлевает подписку, деньги не списываются. Сверху сайта в этом режиме висит жёлтая плашка.

## 4. Настоящая оплата через ЮKassa

1. Зарегистрируйтесь на yookassa.ru и подключите магазин (нужен статус ИП или самозанятого).
2. В личном кабинете ЮKassa, раздел «Интеграция»:
   - «Ключи API»: скопируйте **shopId** и **секретный ключ**.
   - «HTTP-уведомления»: адрес `https://ВАШ_ДОМЕН:8443/pay/webhook`, событие `payment.succeeded` и `payment.canceled`.
3. Допишите в `/etc/vpn-site.env`:
   ```
   PAYMENT_PROVIDER=yookassa
   YOOKASSA_SHOP_ID=ваш_shopId
   YOOKASSA_SECRET_KEY=ваш_секретный_ключ
   ```
4. `systemctl restart vpn-site`

Человек нажимает «Оплатить», уходит на страницу ЮKassa (карта, СБП, SberPay), возвращается в кабинет, и подписка продлевается. Сайт не доверяет содержимому уведомления: он сам спрашивает у ЮKassa статус платежа. Если уведомление задержалось, статус проверяется ещё и при открытии кабинета.

Если ЮKassa требует чеки по 54-ФЗ (обычно да, если вы не самозанятый с «Мой налог»), в запрос создания платежа (функция `pay` в `app.py`) нужно добавить поле `receipt` с почтой покупателя. Напишите, и я добавлю.

Начните с тестового магазина ЮKassa (тестовые ключи из кабинета): оплата проходит тестовыми картами, деньги не списываются.

## Режим предзапуска

Чтобы открыть регистрацию, пока оплата и ключи не готовы, допишите в `/etc/vpn-site.env`:
```
PAYMENTS_ENABLED=0
KEYS_ENABLED=0
```
и выполните `systemctl restart vpn-site`. Люди регистрируются и входят в кабинет, вместо кнопок оплаты видят «Скоро», а сверху висит плашка о скором запуске. Когда будете готовы, поставьте `1` и перезапустите сайт: зарегистрированные аккаунты сохранятся.

## Вход через сервер в России (если операторы режут VPN)

Операторы в России часто «замораживают» соединения с зарубежными серверами: первые секунды VPN работает, потом всё встаёт. Тогда помогает вход через недорогой сервер в России:

```
телефон → российский сервер (HAProxy) → основной сервер (Xray, сайт) → интернет
```

1. На российском сервере (чистая Ubuntu/Debian, свой внешний IP):
   ```
   bash <(curl -fsSL https://raw.githubusercontent.com/dsdsnfdjndfjhbhgfd-ops/vpn-site/main/bridge.sh) IP_ОСНОВНОГО_СЕРВЕРА
   ```
   HAProxy пересылает порты 443 (VPN), 8443 (сайт) и 80 (сертификат) на основной сервер. Для 443 и 8443 он передаёт настоящий адрес клиента (PROXY protocol), поэтому правило «одно устройство» и ограничение попыток входа продолжают работать.
2. На основном сервере:
   ```
   bash <(curl -fsSL https://raw.githubusercontent.com/dsdsnfdjndfjhbhgfd-ops/vpn-site/main/use-bridge.sh) IP_РОССИЙСКОГО_СЕРВЕРА
   ```
   Caddy получает сертификат на адрес российского сервера (`1-2-3-4.sslip.io`), Xray маскируется под него и принимает подключения только через российский сервер. Ключи в кабинете и адрес сайта переходят на российский адрес; старые ключи в приложениях нужно скопировать заново.

Повторный запуск `install.sh` на основном сервере эти настройки не сбрасывает.

## Маскировка под сайты из белых списков

Если мобильный оператор пропускает только разрешённые сайты («белые списки»), VPN можно маскировать под крупный российский сайт. На основном сервере:
```
bash <(curl -fsSL https://raw.githubusercontent.com/dsdsnfdjndfjhbhgfd-ops/vpn-site/main/set-mask.sh)
```
Скрипт перебирает `ya.ru`, `vk.com`, `dzen.ru`, `rutube.ru`, `max.ru`, `www.ozon.ru`, `www.avito.ru`, `www.wildberries.ru` и берёт первый, который подходит для REALITY (TLS 1.3, HTTP/2, X25519 — проверяется через `openssl s_client` с основного сервера). Можно указать сайт сам: `... set-mask.sh vk.com`. Маскировка под адрес своего сайта (из `BASE_URL`, со своим сертификатом): `... set-mask.sh self`. Выбор запоминается (`MASK=` в `vpn-state`), и повторный запуск `use-bridge.sh` его не сбрасывает.

Оператор видит подключение к выбранному сайту, а тот, кто проверит сервер, получает ответ настоящего сайта. Ключи в кабинете обновляются сами (`sni=` в ссылке), в приложениях их нужно скопировать заново.

Ограничение: если белый список проверяет не только имя сайта, но и адрес сервера, маскировка не поможет — нужен вход (российский сервер) у хостинга, чьи адреса в списке разрешённых.

## Запасной ключ: Trojan внутри сайта

Второй способ подключения на случай, если основной ключ (VLESS Reality) не работает. На основном сервере:
```
bash <(curl -fsSL https://raw.githubusercontent.com/dsdsnfdjndfjhbhgfd-ops/vpn-site/main/trojan.sh)
```
VPN прячется внутри сайта: телефон подключается к тому же адресу и порту, что и сайт (`BASE_URL`, через российский вход, если он есть), с настоящим сертификатом Caddy, а Xray отвечает только по секретному пути (`TROJAN_PATH=` в `vpn-state`): Caddy отдаёт этот путь в Xray (Trojan + WebSocket на `127.0.0.1:10443`), всё остальное — сайту. Для оператора это обычный HTTPS к сайту, а кто откроет адрес сам, увидит сайт. Российский сервер настраивать не нужно.

Ключи общие: пароль Trojan — это id ключа VLESS, сайт выдаёт и удаляет ключ сразу в обоих входах, а Xray получает от Caddy настоящий адрес телефона, так что правило «одно устройство» действует и здесь. В кабинете у каждого ключа появляется «Запасной ключ: Trojan». Скрипт обновляет код сайта, проверяет подключение (локально и через вход) и при неудаче возвращает всё как было. Выключить: `... trojan.sh off`.

## Если через российский сервер всё «замирает»: обратный туннель

Признак: сайт через российский вход открывается, но не догружается (белая страница), а VPN подключается, но данные не идут. Причина — фильтр на стороне российского сервера: соединения, которые он сам открывает к зарубежному серверу, замирают после 16–20 КБ. Соединения, открытые из-за границы в Россию, так не режутся, поэтому основной сервер сам подключается к российскому по SSH и держит туннель, а HAProxy на российском сервере пересылает подключения в него (прямой путь остаётся запасным и включается сам, если туннель пропал).

1. На основном сервере:
```
bash <(curl -fsSL https://raw.githubusercontent.com/dsdsnfdjndfjhbhgfd-ops/vpn-site/main/tunnel.sh)
```
   Он проверит, замирает ли связь, создаст ключ и службу `vpn-tunnel` (ssh -R на порты 20443/20843/20080 российского сервера, только 127.0.0.1), разрешит Caddy принимать PROXY protocol с 127.0.0.1, включит сжатие страниц и напечатает команду для российского сервера.
2. На российском сервере — напечатанную команду (`… tunnel.sh ru 'ssh-ed25519 …'`). Она заводит пользователя `vpntunnel` без пароля и командной строки (ключ разрешает только эти порты), переключает HAProxy на туннель и проверяет загрузку файла больше порога.

## Проверить и починить одной командой

На любом из серверов:
```
bash <(curl -fsSL https://raw.githubusercontent.com/dsdsnfdjndfjhbhgfd-ops/vpn-site/main/fix.sh)
```
Основной сервер: программа сайта, Caddy, Xray, туннель и проход через российский вход (с проверкой «замирания» на файле больше 20 КБ). Российский: HAProxy, туннель, связь с основным. Перезапускает упавшее, возвращает сломанные настройки из резервных копий, остальное объясняет.

## Один ключ — одно устройство

Одна подписка даёт один ключ (`MAX_KEYS=1`), и ключ работает только на одном устройстве одновременно.

Как это работает. Раз в 30 секунд сайт спрашивает у Xray, с каких IP сейчас подключён каждый ключ (команда `xray api statsonlineiplist`). Если ключ дольше 6 минут подряд работает из двух разных сетей, это нарушение:

1. Первое: ключ отключается на 15 минут, в кабинете появляется предупреждение. Потом ключ включается сам, с той же ссылкой.
2. Второе: ключ удаляется, создать новый и оплатить подписку человек уже не может. В `/admin` у него пометка «ключ удалён» и кнопка «Вернуть доступ».

Почему 6 минут: когда телефон переходит с Wi‑Fi на мобильный интернет, старое соединение ещё до 5 минут числится в Xray. Адреса из одной подсети (/24) считаются одним устройством. Два устройства в одной домашней сети выходят в интернет с одного адреса, их не отличить.

При первом запуске сайт сам дописывает в конфиг Xray API (`127.0.0.1:10085`), статистику и учёт адресов и один раз перезапускает Xray. Нужен свежий Xray (проверено на версии 26.3), проверить: `xray version`. Если Xray старый, сайт пишет в журнал `xray api is not working, device limit is off` и работает без ограничения. Обновить Xray: `bash -c "$(curl -L https://github.com/XTLS/Xray-install/raw/main/install-release.sh)" @ install`, затем `systemctl restart vpn-site`.

Новые ключи теперь добавляются в Xray через API, без перезапуска, поэтому связь у остальных не рвётся. При удалении и отключении ключа Xray по-прежнему перезапускается: иначе уже открытые соединения продолжили бы работать.

Настройки (в `/etc/vpn-site.env`): `DEVICE_LIMIT=0` выключает ограничение, `SHARE_MINUTES` и `BAN_MINUTES` меняют сроки.

## Полезное

- Логи: `journalctl -u vpn-site -f`
- Обновить сайт: скопируйте новые файлы в `/opt/vpn-site` и выполните `systemctl restart vpn-site`.
- Резервная копия пользователей и платежей: файл `/var/lib/vpn-site/site.db`.
- Цены и сроки меняются в `PLANS`, после правки: `systemctl restart vpn-site`.
- При удалении ключей Xray перезапускается, и у всех подключённых связь прерывается на секунду (так же работает бот). Новые ключи добавляются без перезапуска.
- Восстановить пароль пользователю пока можно только вручную. Письма с подтверждением почты сайт не отправляет.

## Автоматическая выкладка из GitHub

В репозитории есть GitHub Actions (`.github/workflows/deploy.yml`): после каждого push в `main` сайт сам копируется на сервер и перезапускается.

1. Один раз сделайте шаги 2 и 3 выше (файл `/etc/vpn-site.env` и Caddy).
2. Создайте ключ для выкладки на своём компьютере: `ssh-keygen -t ed25519 -f deploy_key -N ""`, затем добавьте его на сервер: `ssh-copy-id -i deploy_key.pub root@IP_СЕРВЕРА`.
3. В репозитории на GitHub: Settings → Secrets and variables → Actions → New repository secret:
   - `SSH_HOST`: IP сервера
   - `SSH_KEY`: содержимое файла `deploy_key` целиком
4. Вкладка Actions → Deploy → Run workflow. Дальше выкладка идёт сама при каждом изменении.

Это статическая копия из тех же шаблонов (её собирает `build_static.py`), оплата и ключи в ней выключены. Регистрация и вход настоящие: аккаунты хранятся в Supabase, в проекте `dnwubeyihrorwzlfxfsn`, в схеме `vpn` (таблица `vpn.users`, пароли зашифрованы bcrypt). Когда включите оплату и ключи на VPN-сервере, аккаунты из Supabase нужно будет перенести в базу сервера.
